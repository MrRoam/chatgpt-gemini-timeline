# Pin 位置替换交互设计

## 目标

把时间轴工具栏中的 Pin 从“开关”改为“设置位置”动作。

用户每次点击 Pin，都把当前页面内唯一的临时 Pin 设置到当前滚动位置。已有 Pin 时，新位置直接替换旧位置，不出现 Unpin，也不通过再次点击清除 Pin。

## 交互规则

1. Pin 按钮始终显示 `Pin chat`，悬浮提示也始终使用相同文案。
2. 第一次点击时，在当前滚动位置创建黄色 Pin 标记。
3. 页面中已有黄色 Pin 时再次点击，旧标记被当前滚动位置的新标记替换。
4. 页面内始终最多只有一个正式的临时 Pin。
5. Pin 按钮是一次性动作按钮，不是二态开关，因此不使用 `aria-pressed`，也不根据是否已有 Pin 切换为 Unpin。
6. 当前 Pin 仍由时间轴上的黄色标记表达；点击黄色标记仍返回所记录的位置。
7. 不新增单独的清除入口。临时 Pin 随页面刷新或离开当前会话自然消失。

## 实现边界

- 修改 `toggleCurrentTemporaryPin()`：无论是否已有 Pin，都调用现有的设置逻辑，以当前 `scrollTop` 覆盖 `temporaryPin`。
- 修改 Pin 按钮状态同步：按钮文案保持 `Pin chat`，移除开关语义；现有黄色标记的渲染逻辑继续负责表示 Pin 状态。
- 不修改持久化逻辑。临时 Pin 仍只保存在页面内存中，不写入 `chrome.storage`。
- 不改变自动跳到底部时的候选 Pin、黄色标记点击导航或时间轴布局行为。
- 不接回 `manifest.json` 未启用的旧模块。

## 异常与降级

如果尚未找到滚动容器，点击 Pin 仍沿用现有提示并返回失败，不创建或删除任何 Pin。

## 测试设计

调整 `tests/timeline-temp-pin.test.js`，验证以下行为：

1. 首次点击在当前滚动位置创建一个临时 Pin，且不写入持久化存储。
2. 移动滚动位置后再次点击，页面仍只有一个 Pin，并且其记录位置更新为新的 `scrollTop`。
3. 再次点击不会把 `temporaryPin` 清空，也不会移除黄色标记。
4. Pin 按钮始终使用 `Pin chat`，不出现 `Unpin`，并且不带 `aria-pressed` 开关语义。
5. 运行项目约定的时间线交互测试、ChatGPT 原生目录测试、全量测试、语法检查和补丁空白检查。

## 验收标准

用户在任意位置点击 Pin 后，可以通过黄色标记返回该位置；滚动到另一处再次点击 Pin，黄色标记立即代表新位置。整个过程中界面不出现 Unpin，第二次点击也不会清除 Pin。
